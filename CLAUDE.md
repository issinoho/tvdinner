# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Setup and tests (either works; `uv` is faster and doesn't require activating a venv):

```
python3 -m venv .venv && .venv/bin/pip install -e ".[dev]" && .venv/bin/pytest
uv run pytest
```

Single file / single test:

```
uv run pytest tests/test_xtream.py
uv run pytest tests/test_xtream.py::test_load_xtream_vod_maps_streams_to_vod_items
```

There is no linter or type checker configured (no ruff/mypy config in `pyproject.toml`) — `pytest` is the only automated check.

Local package builds (Debian/Fedora/from-source instructions, including exact dependency lists, are in the README's Install section — don't duplicate them here). CI builds all three targets (`.deb`, `.rpm`, Windows installer) via `.github/workflows/release.yml`, triggered on `v*` tags.

## Architecture

**One big interactive session, not a class hierarchy.** `cli.py`'s `play_stream()` is the entire interactive runtime: every overlay/browser (program guide, recordings browser, scheduled-recordings browser, VOD browser, Plex browser, help cheat sheet) is a cluster of closures sharing `play_stream`'s local state via `nonlocal`, not a separate object. Each *flat* browser follows the same shape — `open_X`/`close_X`/`render_and_show_X`/`move_X_selection`/`play_selected_X`, wired to `player.on_key_press`/`unbind_key` only while that view is open — and each view's `toggle_X`/`open_X` closes every other currently-open view first (mutual exclusivity is enforced by hand at each call site, not by a shared "current view" variable). When adding a new *flat* browser-style view, copy this shape from the most recent one (the VOD browser) rather than inventing a new pattern. For a genuinely *hierarchical* one (library → show → season → episode, not just a flat list), copy the Plex browser instead (`cli.py`'s `if plex_creds is not None:` block): one generic `open/close/render_and_show/move_selection/select/back` set driven by a `plex_nav_stack: list[_PlexNavFrame]` — pushing a frame drills in, `ESC` pops one level or closes at the root — rather than bespoke closures per level.

**Every live-channel stream source normalizes into the same `Channel`/`Playlist` model** (`m3u.py`), with one exception. `xtream.py`, `stalker.py`, and `hdhomerun.py` each speak a different login/API protocol but all produce a `Playlist` of `Channel`s, so the guide/favorites/EPG-shift/recording/scheduling/bookmarks code in `cli.py` needs zero source-specific branching — the only source-specific code is the `is_X_url`/`parse_X_url`/`load_X_playlist` dispatch in `main()`. Stalker in particular has no static per-channel URL (a `cmd` field must be exchanged for a real URL via `create_link`); that resolution happens once, up front, at load time, so the rest of the app never has to know. **Plex (`plex.py`) is the odd one out**: it has no live-channel/EPG concept at all, so `main()`'s `is_plex_url` branch never produces a `Playlist`/`Channel` and bypasses the `if not playlist.channels:` gate entirely — it's 100% on-demand, browsed as a tree of `PlexNode`s instead (see the VOD paragraph below).

**VOD is a deliberately separate model, not a `Channel`.** `vod.py`'s `VodItem` exists because a movie has no scheduled airing and doesn't belong in the time-grid guide. Sources: `xtream.load_xtream_vod`/`stalker.load_stalker_vod` (native VOD APIs, fetched non-fatally alongside the live playlist in `main()`), `vod.split_m3u_vod_items` (pulls specific `group-title`s out of an M3U `Playlist` — opt-in via `--vod-group`, since group-title conventions vary too much to guess at reliably), and `plex.resolve_plex_playable` (converts a browsed `PlexNode` leaf — a movie or episode — into a `VodItem` lazily, only at selection time, since Plex's per-level listing calls already return everything needed to browse without a per-item resolve step, unlike Stalker's `create_link`). Every VOD-playing code path (VOD browser, Plex browser) sets the same `playing_vod_item` nonlocal in `cli.py`, so `handle_playback_error`'s resume-on-reopen and reconnect-on-drop logic and `show_vod_info_overlay`'s poster/synopsis/progress overlay (`i` key) work identically regardless of which source the item came from — new VOD sources should plug into this the same way rather than growing their own resume/reconnect/info-overlay logic. The VOD browser (and Plex's resolve step) reuses `playback_positions.py`'s resume store, keyed by stream URL instead of a local file path.

**All on-screen UI is a PIL-rendered RGBA image composited by mpv, never a native widget.** `overlay.py` contains every `render_*` function (guide, programme details, recording/VOD browsers, filter prompt, help sheet) — each returns a `PIL.Image`, which `cli.py` pushes via `player.show_overlay`/`clear_overlay` (`player.py` wraps mpv's `overlay-add` command). Adding a new visual element means adding a `render_*` function here, not a new UI framework dependency.

**JSON-file persistence is a consistent `load_*(path)`/`save_*(path, data)` pair per concern** (`favorites.py`, `bookmarks.py`, `schedule.py`, `playback_positions.py`, the EPG-shifts functions in `epg.py`). Loaders never raise on a missing or malformed file — they return an empty/default value plus a list of warning strings for the caller to print, so one bad entry never blocks startup. Follow this contract for any new persisted state.

**Background timing in `cli.py` follows one of two idioms, depending on how long the work runs.** For something that recurs indefinitely for the life of the session (the playback-position autosave, the schedule poller, the skip-intro/credits marker-window poll) — a `while True:` loop on its own daemon `threading.Thread`, sleeping via a shared `threading.Event().wait(interval)` so it can be woken early for a clean shutdown (see `playback_autosave_stop_event`/`skip_marker_stop_event`, both `.set()` in the shutdown `finally` block). For something that only runs for a short, bounded burst and needs to be cancellable mid-flight (the "Up Next" countdown, the sleep timer, the guide/history logo-refresh debounce) — a cancel-and-reschedule `threading.Timer` chain: a `cancel_X_timer()` closure guarding `if X_timer is not None`, called both before starting a new one and from the shutdown cleanup. Don't reach for a `while True` loop where a `Timer` chain fits, or vice versa — the loop shape is for "always running, rarely doing anything," the `Timer` chain is for "usually idle, occasionally ticking down."

**EPG times need per-channel correction before comparing to real time.** `epg.py`'s `EpgDisplay.shift_for`/`schedule_window` apply a feed's clock-correction shift (global `--time-shift` default plus optional per-channel overrides in `--epg-shifts`); raw XMLTV times are feed time, not corrected time, until passed through these. `tvg_id` is not a reliable unique key across channels — always identify a channel by URL, not `tvg_id`, when doing anything more than EPG lookup.

**Packaging duplicates the entry point per platform.** `windows/tvdinner_entry.py` exists only because PyInstaller needs a real analyzable script rather than the normal `console_scripts` entry point — it just calls `tvdinner.cli.main()`.

### Release versioning

As of 1.0.0, versions follow real semantic versioning (`MAJOR.MINOR.PATCH`): bump `PATCH` for a bug fix, `MINOR` for a backward-compatible new feature, `MAJOR` for a breaking change — not on every single commit the way the pre-1.0 `0.1.0-NN` build-counter scheme did. A release bump touches **five files together**, in one commit separate from the feature/fix commit(s) it covers: `src/tvdinner/__init__.py` (`__version__`), `pyproject.toml` (`version`), `debian/changelog` (new top entry), `CHANGELOG.md` (new top entry, same text, backtick-formatted), and `rpm/tvdinner.spec` (`Version:` line, `Release:` reset to `1` — it's now purely an RPM packaging-revision counter, bumped only if the same version needs repackaging, **not** kept in sync with `__version__` — and a `%changelog` entry formatted `<version>-<release>`, e.g. `1.0.1-1`). Tag as `v<version>` (lightweight tag, matching the `__init__.py` version) and push the tag — note `--follow-tags` won't push a lightweight tag, so push it explicitly (`git push origin master v<version>`). `release.yml` builds from `v*` tags.

**Windows signing is a manual step after the tag.** With the repo variable `SIGN_WINDOWS_LOCALLY=true` (it is), CI does *not* build the installer: it attaches the PyInstaller bundle as `tvdinner-<version>-windows-bundle.zip` to a **draft** release, because `tvdinner.exe` has to be signed before Inno packages it and Certum's SimplySign can't run on a hosted runner. Iain then runs, on Windows with SimplySign Desktop logged in, `.\windows\publish-tvdinner.ps1 <version>` — a preflight wrapper (knows the thumbprint; refuses a wrong checkout, a missing draft, an already-signed release, a closed SimplySign session) around `.\windows\sign-release.ps1`, which signs the executable, builds the installer, signs that, uploads it, drops the bundle and publishes. Not doable from here — it needs a live SimplySign session. So a release isn't finished when CI goes green; it's finished when that script has run. Verified working on 1.43.0 (2026-09-04).

### Testing conventions

One test file per source module (`tests/test_x.py` for `src/tvdinner/x.py`). Network-backed loaders (`xtream.py`, `stalker.py`, `hdhomerun.py`, `plex.py`) are tested by monkeypatching `tvdinner.<module>.requests.get` with a fake dispatching on the request's `action`/`type` params (or, for `plex.py`, the request path) — copy the existing `_fake_get_for` pattern in `tests/test_xtream.py`/`tests/test_stalker.py`/`tests/test_plex.py` rather than a mocking library. `overlay.py` render functions are tested by asserting on the returned `PIL.Image` directly (mode, size, pixel counts for things like selection borders, height comparisons for things like date/group grouping) — there are no golden-image/snapshot tests. `cli.py`'s interactive closures (browser open/close/select, keybindings) are **not** unit-tested for any source, Plex included — they're validated live (see the git history around the Plex work for the mpv-IPC-`keypress` driving technique used to do that in a sandbox with no working X11 input injection).
